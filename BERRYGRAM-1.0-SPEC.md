# 6. КАМЕРА ВІДЕОПОВІДОМЛЕНЬ

Це одна з основних функцій першого релізу.

## Вибір камери

Чотири режими:

1. Завжди передня.
2. Завжди основна.
3. Запам'ятовувати останню.
4. Вибирати камеру жестом.

У четвертому режимі користувач починає жест запису кружечка, піднімає палець, бачить компактне меню двох камер, наводить палець на варіант і відпускає.

Після вибору:

- Відкривається потрібна камера.
- Починається запис.
- Запис автоматично переходить у заблокований стан.
- Не потрібно продовжувати тримати палець.

Збережи можливість скасувати запис.

Не змінюй розташування кружечка в чаті.

**Кружечок залишається праворуч, як у звичайному Telegram.**

Не створюй великий повноекранний інтерфейс камери.

## Якість відеоповідомлень

Три режими.

### Стандартний

Звичайна поведінка Telegram.

### Користувацький

Ручні доступні параметри:

- Роздільність.
- FPS.
- Бітрейт.
- Кодек, якщо підтримується.
- Інші параметри, які реально підтримує телефон.

### Автоматичний

Підбирає параметри за:

- Можливостями камери.
- Апаратним енкодером.
- Продуктивністю телефона.
- Тривалістю запису.
- Розміром файла.
- Якістю з'єднання.

За можливості зберігай хорошу якість захоплення та оптимізуй фінальне кодування.

Не використовуй програмне кодування там, де доступне ефективне апаратне, якщо воно забезпечує сумісний результат.

Не перевантажуй слабкі телефони.

Якщо нестандартний режим не працює, передбач безпечне повернення до стандартної реалізації Telegram.

## Тест камери

Зроби компактний тестовий екран відповідно до попереднього завдання, але не витрачай зайвий час на декоративні елементи.

Головне — функціональність.

Додаткові повзунки зуму, ліхтарик та розширений вибір об'єктивів залишаємо для 1.1.

# 10. ОПТИМІЗАЦІЯ BERRYGRAM 1.0.0

Але не потрібно переписувати Telegram на Rust або створювати власний графічний рушій.

Працюй із поточним Android-кодом.

## 10.1. Швидший запуск

- Не ініціалізуй важкі необов'язкові модулі під час запуску.
- Відкладай завантаження непотрібних компонентів.
- Зберігай швидке відкриття чатів.
- Оптимізуй роботу головного UI-потоку.
- За можливості додай Baseline Profiles для критичних сценаріїв.

## 10.2. Кешування аватарок

Не потрібно розпаковувати велике зображення 1024×1024, якщо воно відображається в маленькому кружечку.

Використовуй відповідні thumbnail-версії.

Завантажуй великі зображення лише там, де це потрібно.

Не зберігай зайві копії одного bitmap.

Розумно обмежуй memory cache.

Збережи плавний перехід від мініатюри до повнорозмірного зображення.

## 10.3. Текст і довгі чати

- Не розміщуй всю історію чату одночасно у видимому дереві UI.
- Використовуй механізми віртуалізації та повторного використання елементів Telegram.
- Перевір дорогі операції розмітки тексту.
- Не перераховуй layout без необхідності.
- Уникай зайвих алокацій під час скролінгу.
- Оптимізуй довгі повідомлення й повідомлення зі складним форматуванням.

Не зламуй emoji, спойлери, посилання, цитати або інші можливості повідомлень.

## 10.4. GPU та Liquid Glass

- Зменшуй надмірний overdraw.
- Не виконуй дорогий blur без необхідності.
- Не перераховуй незмінні графічні ефекти постійно.
- Використовуй апаратно прискорені шляхи там, де вони реально ефективні.
- Передбач спрощення важких декоративних ефектів для слабких телефонів.
- Не змінюй основну графіку Telegram заради експериментів.

Не потрібно створювати окремі налаштування GPU.

Оптимізація має працювати автоматично.

## 10.5. Багатопотоковість

Перевір обробку:

- Повідомлень.
- Завантаження файлів.
- Бази даних.
- Кешування.
- Архівування.
- Стиснення відео.
- Фонових операцій.

Важкі операції не повинні блокувати UI-потік.

Але не запускай безмежну кількість потоків і не навантажуй усі ядра без потреби.

Використовуй обмежені черги, правильну синхронізацію і пріоритети.

Не порушуй порядок обробки повідомлень та стан MTProto.

## 10.6. Апаратні кодеки

Використовуй доступне апаратне кодування/декодування відео там, де воно забезпечує кращу ефективність і сумісність.

Перевір fallback.

Не змушуй CPU обробляти відео програмно без потреби.

## 10.7. Батарея

Розширюй існуючий розділ Telegram **«Економія енергії»**.

Не створюй дубльований розділ BerryGram Battery Settings.

Додай:

- Адаптивну економію.
- Налаштовуваний поріг заряду, початково 30%.
- Реакцію на різке падіння заряду.
- Відкладення необов'язкових фонових задач.
- Зменшення дорогих візуальних ефектів у режимі економії.
- Контроль зайвих пробуджень CPU.
- Відновлення відкладеної роботи за сприятливих умов.

Якщо заряд різко падає, не роби висновок, що винен саме BerryGram. Просто обмежуй його необов'язкові задачі.

Не опитуй BatteryManager кожної секунди.

Не зупиняй:

- Надходження повідомлень.
- Сповіщення.
- Активні дзвінки.
- Надсилання повідомлень.
- Активне завантаження, яке користувач сам запустив.

Зберігай нормальну поведінку Telegram у фоні.

## 10.8. Що не робимо

- Не переписуємо інтерфейс на Rust.
- Не пишемо власних драйверів GPU.
- Не створюємо окремий Performance Engine UI.
- Не додаємо десятки ручних налаштувань продуктивності.
- Не переробляємо повністю MTProto.
- Не заявляємо вигаданих приростів швидкості.

Для оптимізації використовуй профайлер і вимірювання лише там, де це потрібно, щоб перевірити реальний ефект або знайти причину проблеми.

# 15. RELEASE APK

Після тестування створи справжній:

**BerryGram 1.0.0 Release APK**

Основна архітектура:

`arm64-v8a`

Збірка повинна:

- Мати правильну назву BerryGram.
- Мати вже затверджену іконку.
- Використовувати production Telegram API.
- Мати правильний package ID.
- Мати `versionName` і `versionCode`.
- Бути зібраною у Release-конфігурації.
- Не містити debug-only можливостей.
- Бути підписаною постійним release-ключем.
- Мати перевірений підпис.
- Мати SHA-256.

Якщо release-ключ іще не підготовлений, не створюй і не використовуй тимчасовий debug-підпис під виглядом остаточного. Підготуй безпечну конфігурацію й повідом тільки про необхідну дію.

## Встановлення

Через ADB визнач підключений Android-пристрій.

Перевір установлену версію та підпис.

Не видаляй мою поточну Telegram-сесію.

Не використовуй `adb uninstall` або очищення даних для обходу проблем підпису.

Якщо встановити поверх старого APK безпечно неможливо, зупини саме встановлення, а не всю збірку, і поясни проблему.

Якщо все сумісне, встанови Release APK та перевір запуск.

Коли справді закінчиш поточне завдання, дай короткий підсумок:

1. Що реалізовано.
2. Які перевірки виконано та їхні результати.
3. Які відомі проблеми залишилися.
4. Де лежить Release APK.
5. Чи встановлено його через ADB.
6. Яка версія й git-коміт.
7. Що відкладено до BerryGram 1.1.
